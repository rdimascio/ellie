# Ellie Media Companion (experimental)

This unpacked Manifest V3 extension is a browser-side companion for explicit controls on the selected active tab. Its production permission surface is `activeTab`, `scripting`, and local native messaging; it has no persistent site access, browser-cookie reads, or website-to-household connection.

The exact reviewed origins are `https://www.netflix.com`, `https://www.youtube.com`, `https://tv.youtube.com`, and `https://www.disneyplus.com`. Netflix uses a distinct DOM companion source over the authenticated native-host selection, not the YouTube Accessibility adapter. It reads bounded same-origin title/watch links and at most eight visible horizontal rows, scrolls vertically, scrolls an explicitly chosen observed row, opens one item from a fresh read, and dispatches play or pause only from a single observed watch-page player state. Search is available only when a fresh read identifies exactly one visible, enabled, accessible search field; the companion pins that field and sends one bounded input event. A separate read must observe the resulting `/search?q=…` page and its title links before selection.

YouTube TV has a separate conservative DOM companion. A fresh read on the selected document reports a welcome/sign-in gate, unsupported page, observed scrollable page, or one visible player with a single matching accessible Play/Pause control. It exposes no program titles or inferred links. Vertical scrolling and observed player play/pause are the only mutations; search, selection, and horizontal rows are explicitly unavailable. Welcome, sign-in, account, subscription and payment surfaces are excluded. A play/pause dispatch does not prove which program is playing. Any mutation consumes the observation and reports unknown until a separate read; it is never replayed or switched to another adapter. Actual authenticated YouTube TV control remains unverified and needs an owner-attended session.

Disney+ has its own restricted DOM companion. On an exact `/browse/entity-<UUID>` page, it can read at most 40 visible, uniquely linked same-origin entity cards and open one fresh observed card. It excludes login, profile, modal, subscription and payment controls. Search, scroll and playback remain unavailable; a title link and navigation do not establish playable or authenticated content. An open consumes the read and remains unknown until explicit refresh/read. The [Disney+ navigation guide](https://help.disneyplus.com/en-GB/article/disneyplus-en-mc-navigate-app) documents browsing and search, while the [public entity page](https://www.disneyplus.com/browse/entity-2fa6a394-c272-41ef-afaa-714116cb16f2) exposes title links alongside sign-in and plan controls. Neither supplies a verified authenticated DOM/player contract. Real Disney+ account and playback acceptance remain pending.

The popup can inspect currently visible title links, scroll one viewport or one real horizontal scroll container, open a fresh inspected candidate, and operate exactly one visible HTML video. Opening confirms navigation only. Playback controls verify observed media state and never replay an action after timeout or navigation.

WebMCP discovery is read-only and bounded. It detects the current `document.modelContext.getTools()` surface and reports legacy `navigator.modelContext` separately. Tool metadata is untrusted and no discovered tool is executed. No supported service has an accepted official WebMCP tool integration in this slice.

Run `bun run test:browser-media` to load a generated test-only extension copy in an isolated Chromium profile. The copy adds only a loopback fixture origin and host permission; the shipping manifest and scripts contain no loopback access. This synthetic workflow does not establish live provider support or an `activeTab` gesture initiated outside the browser.
