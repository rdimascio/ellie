# Household assistant delivery queue

This is the working queue for the household alpha. Each completion advances the next ready slice. CI delays, absent OAuth credentials, and attended phone steps block their own items, not independent implementation. Keep at most three implementation agents active, with one coordinating review. Keep changes independently reviewable and distinguish implementation, simulated tests, real hardware, and user-reported acceptance.

The product UI is native-first: SwiftUI on macOS and iPhone. Browser code remains a compatibility and protocol reference; new household interface work targets native views. Preserve the browser-v1 dashboard export path.

## Delivery rules

- Inspect current refs, instructions and open PRs. Verify write access on each working branch before substantial implementation. Preserve existing history and installed household services.
- Read this queue, active agent status and PR state before assigning work. One owner per file or worktree. Define interfaces before parallel dependent work.
- On completion: review the diff, run meaningful Node 24/Bun-managed checks, publish a small PR, record evidence and immediately select the next unblocked item. CI queueing is not a successful check. Never merge failed checks.
- Existing open PRs remain reviewable; merging the stack and deploying it require the applicable user authorization. A published PR is not a released feature.
- If a task blocks on a credential, consent or physical device, record the precise missing step once and continue another ready task. Do not repeatedly ask the same question.
- Maintain three concrete ready items. Replenish from the stated scope rather than creating unrelated work. Prefer usable vertical slices over placeholder-only PRs.
- All public fixtures are synthetic. Store OAuth credentials, phone identifiers, profile files, CA keys, model paths and household data outside the checkout. Exclude transcripts, recordings and private content from routine logs and failure artifacts.
- Background continuation is a scheduled local task, not a guarantee of uninterrupted execution. Checkpoint progress so host availability or usage limits do not lose work. Report only meaningful completions, blockers or decisions.
