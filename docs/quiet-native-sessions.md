# Quiet sessions on iPhone

The native home reads three recent **personal** Ellie Life conversations after the paired iPhone has an explicit `life.account` grant. “See all” pages through at most 20 conversations per request. Tapping a session makes one fresh read of its original request, recent turns, and background tasks linked by the durable result of a turn in that conversation. The actor and task owner must both match the selected personal scope; coordinator desktop jobs are never used as a session feed.

The detail limits recent turns to 12, linked tasks to eight, progress entries to four per task, and finding summaries to bounded text. "Verified finding" appears only for a succeeded task with a verified outcome and at least one current source citation. A completed result without citations stays a result, not a verified finding; missing or changed citations are hidden and flagged for fresh review. It marks omitted older turns or linked work. Task state comes from the durable TaskRuntime, so a queued, paused, failed, or completed task is not described as currently working.

The iPhone uses the existing short-lived native Life session with pinned TLS. Quiet adds only its two paths to the existing GET allowlist, with a bounded response and no redirect. The response decoder rejects extra fields, mismatched IDs, invalid dates/states, oversized text, and malformed pagination. These private reads are memory-only on the phone; backgrounding, enrollment changes, or revoked access clear them, and late results cannot restore them. A failed read removes the displayed snapshot and asks for a fresh refresh. The native screen provides review and the existing separately granted voice-control entry; it adds no text composer, Life chat mutation, account connection, or background task start.

Focused source tests cover actor isolation, durable turn-to-task links and verified progress after a TaskRuntime restart. Four app-hosted iOS unit cases passed on the combined predecessor. After correcting inherited accessibility identifiers and a transparent row hit area, the integrated Simulator UI case passed recent-session navigation, distinct details, See all, existing Voice controls and revocation. The UI fixture uses the production Quiet views with synthetic authorized data; it does not establish a real account session, microphone capture or physical-device acceptance. Current combined CI and conversational Life voice instructions remain separate gates.
