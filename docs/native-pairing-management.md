# Native pairing management

The macOS Devices window exposes **Manage iPhone Pairing** only while an installed coordinator identity is connected. It reuses the existing pinned certificate and controller bearer. A person supplies a bounded phone label and explicitly selects inventory entries that advertise `app.open`; Ellie submits one invitation request with one grant per selected Mac.

The returned version-1 native enrollment payload is decoded with the same canonical wire rules as the iPhone client. The pinned controller delegates the separately configured native-listener origin and leaf pin; they do not need to match the controller API origin or certificate. The Mac requires a canonical HTTPS listener origin and exact lowercase hexadecimal pin, and binds the returned label and grants to the request before rendering the exact canonical payload with Core Image. The iPhone explicitly confirms that delegated origin and grants before trusting the delegated leaf pin. The sheet shows the label, access summary, and server expiry. Hiding or closing the QR only removes it from the window: the coordinator has no invitation-cancellation route, so the code remains usable until it is consumed or expires.

Mutation failures are never retried automatically. A rejected request is distinguished from an uncertain network or response failure. An uncertain invitation can remain usable for up to ten minutes and cannot be discovered through the client-list route, so the UI tells the person to wait rather than immediately create another. An uncertain revocation can be resolved by refreshing the active-client list.

The sheet reads a bounded, exact-shape active native-client list and offers explicit per-client revocation. Losing coordinator authority closes the sheet, cancels its owned request, and clears the in-memory QR. It does not expose or persist invitation codes through logs, URLs, the clipboard, dashboard state, or local files. It adds no credential loader, TLS exception, CLI bypass, account access, or protocol route.

The management transport still shares the controller transport's 128 KiB streaming response cap, five-second absolute deadline, redirect refusal, and exact leaf trust. The production URLSession delegate requires an application/json response before accepting its body; an actual pinned HTTPS regression rejects text/plain. Foundation's parsed media type does not independently count duplicate raw Content-Type header lines.
