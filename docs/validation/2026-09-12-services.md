# Two-Mac service validation — 2026-09-12

This records development validation, not signed-release or household-alpha acceptance. Personal paths, addresses, node/job IDs, credentials, and desktop screenshots are intentionally excluded.

## Environment

- Coordinator: MacBook Pro, macOS 15.1, Node 24.21.0, Bun 1.4.2.
- Execution node: Apple silicon Mac mini, macOS 26.6.2, Node 24.21.0, Bun 1.4.2.
- Existing LAN pairing, certificates, native helpers, and Keychain entries were used. No initialization or pairing was repeated.
- Both roles used their per-user Aqua LaunchAgents. Their process parent was launchd (PID 1); terminal processes did not host either service.
- Controller commands were issued remotely through temporary one-shot GUI LaunchAgents so the MacBook's logged-in Keychain context was retained. Those temporary jobs were removed after each check. SSH alone did not provide the same Keychain context.

Hardware testing exposed and fixed the generic Node identity, terminal-versus-service doctor mismatch, and the macOS `print-disabled` word-value parsing bug. It also exposed confusing CLI connection errors and an inactive local node configuration taking precedence over the coordinator's live-node selection; these are reviewed in separate small changes.

## Automated and simulated coverage

The full Node 24 check covers lint, formatting, generated contracts, type checking, and the automated suite. At application-identity commit `437b817`, 72 tests passed and one platform-specific test was skipped locally. CI also runs on Linux and macOS 15.

Application tests compile and verify a real temporary macOS app and ICNS file. Injected filesystem/build failures cover signature repair, registration retries, rollback during app/plist publication, per-role locks, unmanaged files, path changes, and repeated installation. They use synthetic directories and do not request privacy permissions.

`smoke:services` passed using an inert temporary native app and GUI LaunchAgent: startup, SIGKILL relaunch, descendant-process cleanup, and bootout. It skips LaunchServices registration and does not use household identities, Keychain, or native desktop actions. `smoke:macos` also passed its temporary Swift build/signature and geometry checks; its optional model probe was unconfigured.

Durable-state migration, queued/running recovery variants, cancellation races, persistence failures, absolute network deadlines, reconnect bounds, and inference scheduling use temporary databases, controlled clocks, fake executors, or local test servers. Those tests are not physical inference or sleep/wake results.

## Still unvalidated on hardware

- Physical sleep/wake, logout/login, FileVault login, and startup after reboot.
- Removal and renewed installation of the node app after its Accessibility grant; the working grant was preserved during overnight testing.
- Cancellation or crashes midway through a native side effect, and suppressing later actions in an active multi-action sequence.
- A real link loss, changed coordinator LAN address, locked Keychain, and denied-permission variations beyond the observed Ellie Node consent check.
- Local model inference, simultaneous independent inference workers, and optional distributed MLX.
- Signed/notarized release installation, updates, rollback across schema changes, and Accessibility grant continuity across rebuilt versions. These source bundles are signed ad hoc.
