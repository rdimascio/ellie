# Native phone browser UI validation — September 15, 2026

Candidate `aacf5c961580f2d8d7cd84de2a469f349f3e49a9` adds a focused UI acceptance test for the native iPhone path from reviewed voice text to explicit browser controls. Transcription remains editable and never dispatches automatically. Search requires a current page read and an explicit reviewed action; selecting a result and using playback controls requires a fresh observed page. Leaving or backgrounding an active browser wait cancels it, reports a post-dispatch unknown outcome and does not authorize replay.

On Xcode 16.2, one focused SwiftUI UI test passed on a newly created iPhone 16 Pro Simulator with iOS 18.3.1. The 24.420-second test exercised synthetic record and transcription, transcript review, explicit initial read, reviewed search, explicit updated read, navigation into `BrowserControlView`, selection of one observed result, backgrounding during the dispatched wait, an unknown result after activation and an unchanged mutation count during an additional no-replay interval. The test used only DEBUG-compiled in-memory credentials, recorder and transports.

An unsigned Release Simulator build passed with signing disabled. The fixture launch argument and mutation label found in the Debug executable were absent from the Release executable. The app entry point owns no production stores; the normal dashboard and enrollment stores are constructed by a separate normal-root view that the fixture branch does not instantiate. The exact iOS source archive used for this record has SHA-256 `0b6fad6411cfdacbc15e05aa55bf34a5ccc590ede18c04168ef1820dcbff546d`.
