# Production readiness review

This record separates release engineering from acceptance of the installed household system. The owner requested the next development milestone to meet a production standard. The reviewed packaged candidate is still a development release; passing source tests alone does not establish that standard.

## iPhone runner diagnosis

PR59 at `c88c58e354e4da2dd831c5cc11447f406c41e1ed` had two failed native jobs, `103862281617` and `103862286300`. The first retained run passed the repository gate, native builds, geometry checks and 158 Swift tests. Its iPhone UI runner reached testmanagerd session setup but no UI test began before the existing 600-second test deadline. Its diagnostic reported `stage=xcode-test outcome=timeout`; the transport stage was skipped. Do not treat earlier stages passing as a passing native job.

The retained result selected iOS 26.2 while Xcode 16.4 supplied simulator SDK 18.5. The script previously chose the newest installed runtime without considering the selected toolchain. This is a concrete selection defect and a plausible contributor to the stall, not proof of its sole cause. A [first-hand runner-images report](https://github.com/actions/runner-images/issues/12777) describes a different simulator startup failure with the same Xcode/newer-runtime pattern.

[PR70](https://github.com/rdimascio/ellie/pull/70), final source `186c14fa8c1a375f19a094ef8aa9db674ef65f34`, adds strict version parsing, bounded platform diagnostics and a deterministic runtime policy. It prefers the newest available iOS runtime at or below the selected SDK; if none exists, it permits a runtime in the same SDK major generation. It excludes newer major generations. This is the runner's conservative selection policy, not a complete statement of Apple's support matrix.

A read-only MacBook inventory found Xcode 16.2, SDK 18.2 and the available iOS 18.3.1 runtime. That known-working test host exposed an overly restrictive first draft that rejected every runtime newer than the SDK. The follow-up preserves this same-generation case. Apple's [system requirements](https://developer.apple.com/xcode/system-requirements) separately describe SDK versions and supported simulators; an SDK number is not a universal simulator upper bound. No runtime installation or global Xcode selection was changed.

The first reviewed PR70 commit passed five focused cases and the complete gate (284 passed, one skipped). The final two-file selection follow-up passed the same five focused cases, lint and type checks. Root independently reran the five initial focused cases and the final two selector cases. These are synthetic command fixtures and pure selection tests, not a physical iPhone or Simulator run.

The existing iOS runner also signaled negative process-group IDs after its direct child closed. [PR71](https://github.com/rdimascio/ellie/pull/71), `c24ce2e8e50c90a7f06a41d00dbf9df1c7b5384b`, replaces that inherited path with retained direct-child handles, bounded TERM/KILL/reaping, read-only group absence probes and evidence retention on uncertainty. Cleanup failure fails the run; a retained result blocks a new run from overwriting it. The final eight focused cases passed independently under root review. The author's earlier full 286-pass/one-skip gate preceded the final test hardening and is not attributed to the final hash.

Root combined both reviewed histories at `4d9980b074fdca6e505ebb313680afbcd743458f`, resolved their shared diagnostic-fixture changes, and published that head in PR59. The combined ten focused cases and complete repository gate passed: **289 passed, one skipped**, with lint, formatting, contracts, type checks and web build passing. The full log is retained locally as `ellie-integration-4d9980b-full-check.log`.

The exact clean combined source then passed **two iPhone UI tests** on the physical MacBook's Simulator, using Xcode 16.2, SDK 18.2 and iOS 18.3.1. The run took 94,531 ms overall and reported successful shutdown, simulator deletion and derived-data removal. Root independently confirmed the exact created simulator, derived-data directory and result bundle were absent afterward. This is real Simulator execution on a physical Mac, not physical iPhone, microphone, LAN-command or installed-service acceptance. No test retry, runtime installation, global toolchain change or weaker UI assertion was used. The runner log is retained locally as `ellie-ios-runner-4d9980b-macbook.log`.

One further older-candidate native failure (`34809141787/103866784428`, still at `c88c58e3`) timed out during simulator boot readiness before xcodebuild started and reported shutdown/deletion failure. That separate pre-test failure is retained; it is not an application assertion and does not prove a unique cause for all CI stalls. GitHub native acceptance of the newly combined head remains a separate check.
