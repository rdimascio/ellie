# Browser accessibility runtime

Ellie includes a bounded macOS accessibility adapter and a persistent helper for reading an authorized browser page and dispatching a small set of low-impact actions. The packaged node connects this adapter to canonical browser jobs. This is development integration: an installed extension, authenticated native host, real browser actions, and the physical phone voice flow still need acceptance.

Browser execution remains an explicit node opt-in through the private reviewed operation registry. Packaged execution uses captured helpers and Node under the same payload; a source checkout alone does not provide those executables. The native-host manifest planner produces an artifact for an already admitted release; it does not install the host or grant Accessibility consent. Existing identities, Keychain credentials, and browser profiles are not changed by this implementation.

The Swift broker derives the native-host peer from the Unix socket audit token, verifies its PID version, executable and live signing identity, and rechecks the captured signed browser ancestry before forwarding each request. A process identifier supplied by a phone, extension, or network request is never authority. Safari and Arc are checked against fixed signing requirements. The browser ancestor is bound by PID, launch timestamp, executable and code hash; this public-API tuple is weaker than possessing the browser's own audit token and is not described as an exact audit-token guarantee.

An observation belongs to one adapter instance and one authorized page object. A later read invalidates its prior generation. Every action revalidates the process launch identity, focused window, WebArea, address field, full URL, document revision, generation, and retained accessibility element identity. Stale, ambiguous, revoked, unbound, or changed targets fail closed. The node chooses WebMCP first; Accessibility requires an explicit valid tab binding that reports unsupported WebMCP. A malformed or disconnected bridge does not authorize fallback, and an attempted operation is never retried through another backend.

Traversal limits node count, depth, attribute calls, text, items, and AX messaging time. The internal two-second value is a checked AX traversal budget. The node imposes a fifteen-second request deadline around the helper, including synchronous Security.framework verification, then bounds termination and reaping. Malformed responses retire their helper generation. Uncertain cleanup retains ownership and blocks replacement; cancellation or a crash never replays a request. An explicit fresh status request can replace a stale session after verified cleanup, while an old action remains rejected.

The broker keeps a private single-instance lock and records the owned socket identity. Restart can remove a verified stale socket after a crash, but refuses live, foreign, or ambiguous entries. Normal idle browser disconnects revoke the context without exhausting the process restart budget. Process failures use three bounded replacement attempts; a fresh authenticated connection is required before admitting work.

Scroll, search, selection, and playback dispatch report an unverified effect. Selection is restricted to observed unique YouTube watch links; it is not an arbitrary button-click capability. Search has separate value-setting and confirmation boundaries; failure after setting the value is terminal and unknown. Both an unverified dispatch and a possible-dispatch failure produce a canonical unknown result and durable job state. The adapter never evaluates JavaScript, accepts selectors or arbitrary URLs as actions, or treats a successful accessibility call as proof that playback or navigation completed.

Tests use synthetic accessibility trees, isolated helper processes, compiled Swift fixtures, and the actual coordinator/node job path. They cover strict replies, cancellation, crashes, reconnects, stale socket recovery, retained cleanup uncertainty and durable unknown outcomes without replay. Production broker compilation is separate from fixture execution. Actual Safari and Arc accessibility layouts, browser-parent correlation, TCC behavior, and end-to-end dispatch have not been accepted on real browsers.

The `ellie browser pursue` CLI loop (see decision-routing.md) is an operator-bounded consumer of this existing `read`/`select`/`scroll` contract. It adds no element kind, no Swift change, and no new capability: it reads this adapter's bounded observation, proposes at most one already-supported action per `/v1/commands` request, and reports every dispatch `unknown`, exactly like any other browser command. There is no replay across steps; each step is a fresh read taken after the previous dispatch. Its coverage is synthetic AX fixtures only, described in the previous paragraph's terms.
