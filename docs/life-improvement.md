# Private improvement review

`LifeImprovementEngine` turns one to three explicitly selected, actor-private `learning-feedback-v1` examples into a reviewable proposal. It sends only those complete examples and an optional goal to the configured local model. It then replays each original prompt offline with the candidate instruction. Preview calls receive neither the recorded answer nor the correction, and they cannot execute tools or life operations.

`propose()` enforces exact feedback revisions, the actor's current chat epoch, caller cancellation and an optional context callback before and after every model await. A harness admits at most two actual workflows. Its default whole-workflow deadline is 90 seconds (configurable from 1 to 120 seconds). A timed-out noncooperative model retains its admission slot and cannot persist late output. Hosts should call `settleActive()` before closing the underlying store; a `false` result means a model callback is still live and the store must remain open.

Model requests preserve whole selected fields under a 64-KiB serialized UTF-8 ceiling. Oversized selections are rejected rather than shortened. Candidate and preview responses have strict JSON schemas; one formatting/schema repair shares the original thirty-second model deadline. Transport failures are not retried, and a second invalid result stops the workflow before a proposal is saved. Host retention permits twenty proposals, including adopted and dismissed audit records; delete an old proposal or its adopted guidance to free capacity. The database filters proposal markers before applying that limit, so unrelated routines cannot hide retained proposals.

Ready proposals are private routine records marked `learning-improvement-v1`; they do not enter ordinary model context or guidance. `adopt()` atomically transforms the same row into enabled `teaching-guide-v1` guidance and retains proposal audit metadata. Later teaching revisions preserve that metadata. `dismiss()` keeps a reviewable inactive proposal. Changed or deleted feedback makes a ready proposal stale, hides its replay previews, and blocks adoption. An already adopted instruction remains user-controlled guidance if its original feedback is later deleted.

The replay adapter withholds the reference response and correction, but a generated instruction can still contain an illustrative answer from the selected feedback. Matching that answer is therefore not independent evidence of improvement. Candidates can also overgeneralize or add unnecessary conditions. Review the exact proposed instruction and its limited example reply before adopting it. Personal guidance applies in the personal space; it does not modify a group's guides.

This workflow is an offline example replay for user review. It does not train model weights, run a held-out evaluation, prove general quality, or adopt instructions automatically. The [real-model acceptance](life-model-validation.md) records both the successful behavior and the observed limitations.
